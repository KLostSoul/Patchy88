# Patchy88 검증 모델

## 1. 목적

Patchy88의 핵심 목표는 일반 IPS 패처처럼 무조건 바이트를 덮어쓰는 것이 아니라, **패치 대상 원본 데이터가 실제로 지원되는 상태인지 확인한 뒤 적용하는 것**입니다.

## 2. 전체 파일 해시를 주 검증값으로 쓰지 않는 이유

PC-8801 D88은 디스크/섹터 컨테이너입니다. 패치와 무관한 저장 데이터 또는 이미지 직렬화 차이 때문에 전체 파일 해시가 달라도 패치 대상 바이트는 동일할 수 있습니다.

바리스 1 Disk A에서 실제로 확인한 두 원본 전체 SHA-256:

```text
ae9e0d57219763cc575e66d38e92c78e7f3fc7a6acdeba0e5f13d7f7dd920a44
7404998ee7e94e14d065a11e55bc26f7f8733202eec6774610a20a6d0b5a1fdf
```

두 파일의 전체 SHA-256은 다르지만 `Valis_Korean_Disk_A_Patch_Ver_1.02.ips`가 건드리는 범위를 전부 비교한 결과:

```text
IPS record count: 1282
RLE record count: 0
patched/touched bytes: 23330
minimum offset: 12651 (0x316B)
maximum offset inclusive: 121684 (0x1DB54)
target-byte differences between the two source images: 0
```

즉 패치 대상 23,330바이트는 완전히 같았습니다.

## 3. 표준 IPS의 한계

표준 IPS 레코드에는 다음이 들어 있습니다.

- 출력 오프셋
- 교체 데이터 또는 RLE 데이터

원본 바이트는 들어 있지 않습니다. 따라서 IPS 파일만으로는 안전한 원본 검증을 할 수 없습니다.

Patchy88은 지원 원본에서 패치 대상 영역의 적용 전 상태를 별도 매니페스트에 기록합니다.

## 4. 레코드별 before/after 검증

각 IPS 대상 영역에 대해:

```text
current == before → ORIGINAL
current == after  → ALREADY_PATCHED
```

전체 레코드 상태를 종합해서 다음과 같이 판정합니다.

- `ORIGINAL`: 모든 대상 영역이 적용 전 상태
- `ALREADY_PATCHED`: 모든 대상 영역이 적용 후 상태
- `PARTIAL`: 적용 전/후 상태가 혼재
- `INCOMPATIBLE`: before/after 어느 쪽에도 맞지 않는 대상 영역 존재

부분 패치와 호환되지 않는 데이터는 적용하지 않습니다.

## 5. IPS 자체 검증

패치 적용 전 다음을 확인합니다.

- IPS 헤더/EOF 구조
- 일반 레코드 및 RLE 레코드 파싱
- 오프셋/길이 범위
- 매니페스트에 기록된 IPS SHA-256
- 대상 파일 크기/형식 조건

잘못된 IPS는 원본 파일을 수정하기 전에 거부합니다.

## 6. 출력 및 백업

패치 결과는 원본에 직접 덮어쓰지 않습니다.

```text
원본: game.d88
백업: game.d88.bak
결과: game(K).d88
```

기존 백업이 있으면:

```text
game.d88.1.bak
game.d88.2.bak
...
```

순으로 새 백업을 만들며 기존 백업을 덮어쓰지 않습니다.

## 7. 임시파일과 사후검증

Patchy88은 패치 결과를 먼저 임시파일에 생성합니다.

```text
사전검증
→ 임시파일 생성
→ IPS 적용
→ after 해시 사후검증
→ 성공 시 (K) 결과 확정
```

사후검증 실패 시 정상 결과로 승격하지 않습니다.

## 8. 바리스 II 폴더 자동 식별

바리스 II판은 사용자가 지정한 폴더 바로 아래의 `.d88`, `.rom`을 검사합니다.

파일명은 Disk A~G/KANJI1 판정 조건이 아닙니다. 각 대상 프로필의 before/after 해시와 비교해 내용으로 식별합니다.

다음 조건 중 하나라도 있으면 일괄 작업을 시작하지 않습니다.

- Disk A~G/KANJI1 중 누락
- 동일 대상 후보가 둘 이상 발견되어 모호함
- 부분 패치
- 호환되지 않는 원본
- IPS 변조/손상

8개가 모두 정상일 때만 임시 패치를 준비합니다.

## 9. 바리스 II 트랜잭션 방식

바리스 II는 8개를 한 번에 처리하므로 한 파일씩 바로 확정하지 않습니다.

1. 8개 전체 사전검증
2. 8개 임시 결과 생성
3. 8개 전체 사후검증
4. 모두 성공한 경우에만 실제 결과 확정
5. 확정 단계 오류 시 이미 처리한 항목도 복구하도록 설계

테스트에서 Disk A를 일부만 패치한 상태로 만들었을 때 전체 작업을 거부하고 `.bak` 및 `(K)` 결과가 하나도 생성되지 않는 것을 확인했습니다.

## 10. 현재 D88 호환 범위

현재 구현은 **D88 파일의 flat offset**을 사용합니다.

논리 섹터 정규화는 하지 않습니다. 따라서 동일한 논리 섹터 데이터를 가진 이미지라도 D88 직렬화/오프셋이 다르면 패치 대상 영역 검증에서 거부될 수 있습니다. 이 동작은 잘못된 위치에 IPS를 적용하는 것보다 안전하게 실패하는 것을 우선한 설계입니다.
